# SOEN-343-Team-Out-Of-Office

## How to run Step-by-Step
1. Clone Repository
2. `docker compose up` to run the website (frontend and backend)
3. `docker compose down` to stop the website

## Requirements

- Java 17 or newer (Maven is included through the Maven Wrapper, no install needed)
- Node.js 20 or newer

## Run the backend

```
cd src/backend
./mvnw spring-boot:run
```

The server runs on http://localhost:8080

### Seeded Accounts

One account per role is seeded automatically every time the backend starts (see table below). The usernames and shared demo password are configured in application.properties. Existing accounts with these usernames are left unchanged, so restarting never creates duplicates. Do not use these credentials for a public deployment.

| Role | Username | Password |
|---|---|---|
| Customer | `customer` | `pass1234` |
| Restaurant | `restaurant` | `pass1234` |
| Courier | `courier` | `pass1234` |
| Operator | `operator` | `pass1234` |

### Account API

Account creation uses the **Facade pattern**: `AuthController` calls
`AccountFacade`, which handles account-type selection, password hashing, and
database storage behind one registration method.

Accounts are stored in the local H2 database at `src/backend/data/accounts.mv.db`.
The numeric `userId` is generated by the database and increases as accounts are inserted.
Passwords are stored as BCrypt hashes, not as plain text.

Register with `POST /api/auth/register`. Send an `accountType` of `CUSTOMER`,
`RESTAURANT`, `COURIER`, or `OPERATOR`. For example, a customer request is:

```json
{
  "username": "casey",
  "password": "a-long-password",
  "accountType": "CUSTOMER",
  "name": "Casey",
  "deliveryAddress": {
    "lat": 45.5,
    "lng": -73.6
  }
}
```

Customers require `name` and `deliveryAddress`. Restaurants require `name` and
`position`; their initial status is `CLOSED`. Couriers may include a `position`
and start `OFFLINE`. Operators need only `username` and `password`. Passwords
must be at least eight characters. The response includes `userId`, `username`,
and `accountType`, but never the password or its hash.

Use `POST /api/auth/login` with `username` and `password` to log in, and
`POST /api/auth/logout` to end the session. Browser requests from the frontend
should use `credentials: "include"` so the session cookie is sent; the backend
allows the Vite origin `http://localhost:5173` by default. Set
`APP_CORS_ALLOWED_ORIGIN` to change it.

For now, operator self-registration is enabled to support the requested account types;
should be restricted later to an administrator or invitation flow before exposing registration
to the public.
